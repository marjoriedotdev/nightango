## Findings considered and rejected

- Takeover of the suspended GitHub namespace through the update check:
  the account is back (owner, 2026-11-13). The residual risk is the one of
  any release host.
- Upgrade to React 19: React 19 ships no UMD build, which the loader needs
  to load React from cdnjs with SRI. Staying on 18.3.1 is the pinned
  choice of rule 5.
- Upgrade jsdom 24 to 31: a test-only dependency with no known
  vulnerability (`pnpm audit`: none). No cost to staying.
- Declarative refresh in the full profile frame: the HTML standard blocks
  it in a sandboxed frame without `allow-scripts`. Hardening at best.
- Focus on Cancel in confirmation dialogs (`data-autofocus` loses to the
  first button): it makes Enter cancel, which is the safer default. A
  deliberate change of that default belongs to the owner.
- "A suite can stop early and still pass": `live_login` does fail on an
  uncaught error, and `voice` has a catch. The remaining case (zero
  previews in `check_ds`) is not worth a runner change.
- Group settings save: the first confirmation ends the "waiting" state
  early. The page then shows the group's real settings and the toast says
  "sent", not "applied". Only the "didn't confirm every change" notice can
  be lost. Low value for the risk of touching that draft logic.
- Duplicated prototype and live settings screens and actions: real, but a
  redesign of the prototype (a simulated bridge), not a plan-sized fix.
- Structure of `src/bridge/live-bridge.js` (one 99 KB closure): real, and
  better done after plans 003 to 017 have stopped moving its lines.
- Stricter `allowed_calls` scan (aliases, `WebSocket`, the design system
  bundle): no escape exists today. Worth doing when that suite is next
  touched.
- Link warning shows the raw address, and the sign-in stylesheet guard
  matches literals only: low likelihood, first-party input.
- Smaller view defects confirmed but not planned, each a few lines: an
  edit started during a PM file upload is dropped (`src/views/dm.js:311`),
  the "New messages" button appears for hidden messages
  (`src/views/group.js:266`), a dismissed announcement banner does not come
  back in live (`src/app/live-ops.js:208`), a failed copy reports success
  (`src/core/util.js:174`), menus do not close on scroll inside the Shadow
  DOM (`src/core/ui.js:198-206`), Escape in a menu also closes the dialog
  under it (`src/core/ui.js:102`, `:447-450`), two tabs overwrite each
  other's per-account data (`src/app/live-state.js:92-98`).
- Performance: `RichText` parses member HTML again on every state change
  (`src/core/rich-text.js:224-235`), TikTok and X previews are read for
  every loaded row instead of the rows in view
  (`src/views/message.js:243-248`), `live_ui` waits about 60 s of real
  time. Not measured in a browser. Candidates for a later pass.
- ADR-0005 says "even compromised page code cannot query another profile
  through the bridge", while the loader reads the account name from the
  page (`src/loader/skin-loader.js:26-35`). A wording fix for the owner.
